# Benchmark: Kagoni vs the raw `docker` CLI

Generated by `benches/run.py`. Every number here is reproducible — see
[Reproducing](#reproducing).

- **Tokenizer:** tiktoken/cl100k_base
- **Kagoni:** kagoni 0.1.0 · **engine:** orbstack
- **Fixture:** 6 containers from `benches/fixtures/bench-stack.compose.yml`

## Per scenario

| Scenario | Raw tokens | Raw calls | Kagoni tokens | Kagoni calls | Ratio |
|---|---:|---:|---:|---:|---:|
| Fleet health | 31,018 | 14 | 2,340 | 3 | **13.3×** |
| Crash-loop triage | 2,609 | 2 | 431 | 1 | **6.1×** |
| Logs, repetitive | 30,420 | 1 | 380 | 1 | **80.1×** |
| Logs, low repetition | 5,065 | 1 | 1,321 | 1 | **3.8×** |
| Container listing | 176 | 1 | 400 | 1 | 0.44× ✗ |
| **All scenarios** | **69,288** | **19** | **4,872** | **7** | **14.2×** |

`✗` marks a scenario where Kagoni costs **more** than the CLI. Those are
here on purpose.

## The fixed cost

Kagoni's 18 tool schemas and handshake instructions are always-on context —
present in every session whether or not a tool is called:

| Tool schemas (18 tools) | 4,177 tok |
|---|---:|
| Handshake instructions | 299 tok |
| **Resident per session** | **4,476 tok** |

Against a single fleet-health question:

    raw CLI                  31,018 tok
    kagoni (calls only)        2,340 tok    13.3x cheaper
    kagoni (+ resident)        6,816 tok    4.6x cheaper, all-in

Break-even is roughly **one** non-trivial container question per session. Below
that, the schemas are pure overhead — an argument for loading Kagoni where you
actually use it rather than in every project.

## Reading this honestly

- **The win is concentrated.** Nearly all of it comes from `inspect` projection
  and log clustering. Those dominate real troubleshooting, which is why the
  headline number is large — but the small reads genuinely cost more.
- **Clustering depends on repetition.** The two log scenarios differ by an order
  of magnitude for exactly that reason. Real service logs are usually closer to
  the repetitive case; a one-shot batch job is closer to the varied one.
- **Call count matters as much as tokens.** Fewer round trips is less latency and
  fewer chances for an agent to lose the thread. Wall clock is deliberately NOT
  reported: this harness starts a fresh Kagoni process for every call, while a real
  MCP session starts the server once, so any timing here would overstate Kagoni's
  cost. Call count is the honest proxy.

## Reproducing

```bash
cargo build --release
pip install tiktoken   # for real token counts
docker compose -p kagoni-bench -f benches/fixtures/bench-stack.compose.yml up -d
sleep 10               # let the fixtures emit their logs
python3 benches/run.py --sync-readme > docs/BENCHMARK.md
docker compose -p kagoni-bench -f benches/fixtures/bench-stack.compose.yml down
```
